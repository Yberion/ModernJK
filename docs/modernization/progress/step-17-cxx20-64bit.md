## 2. What changed

**Build.** `CMAKE_CXX_STANDARD` 20, required, without extensions, for every target (the `-std=c++11` of `CMAKE_CXX_FLAGS` and the C++17 forced on `qlibm` removed); with MSVC, `/std:c++20` implies the strict mode `/permissive-`. The configuration stops on a target that is not 64-bit, on a system other than Windows, Linux and macOS, and on a processor other than x86_64 and arm64 (`Architecture` is `x86_64` or `arm64`). Removed: the `x86`, `i386`, `arm`, `ppc` and `ppc64` branches, the BSD block, `/arch:SSE2`, `-msse2`, `-mstackrealign` and `-mfpmath=sse` (none of them changes the x64 code: the 280 C objects of the clang build compiled again with `-msse2` are identical, the COFF time stamp set aside), the `WIN64` definition (the code tests `_WIN32` and the compiler's own macros), the option `UseInternalOpenAL` and the OpenAL and EAX blocks (MSVC in 32-bit only), the x86 branches of `lib/SDL2`, the installation of `OpenAL32.dll` and `EaxMan.dll` (32-bit DLLs copied into the x64 installations), `cmake/Toolchains/i686-w64-mingw32.cmake` and `linux-i686.cmake`.

**Code removed.**
- `shared/qcommon/q_platform.h`: Windows x86_64 only (an `#error` otherwise), macOS x86_64 and arm64, Linux; the 32-bit Windows, Alpha, PowerPC, i386, kFreeBSD and BSD branches and `idx64` removed.
- `id386` and `idppc` (both `q_shared.h`) and their uses: the x86 assembler mixer of MSVC (`codemp/client/snd_mix.cpp`), the syscall branch of `vm.cpp` and `vmachine.cpp`, the PowerPC blocks of `tr_surface.cpp` (rd-vanilla, rend2: the last `register` keywords) and `tr_light.cpp` (rend2), the x86 macros of `mp3code/port.h` (both trees); Solaris (`__SUNPRO_C`, `sun`, `net_ip.cpp`), OS/2 (`__EMX__`), the BSD branches of the `qgl.h` files.
- The OpenAL and EAX sound path, compiled only by MSVC in 32-bit: every `USE_OPENAL` block of `snd_dma.cpp`, `snd_mem.cpp`, `snd_local.h` (both trees) and `shared/sdl/sdl_sound.cpp` (about 2,600 lines per `snd_dma.cpp`), the `client/OpenAL` and `client/eax` headers, `lib/OpenAL32.lib`, `lib/ALut.lib`, the `OpenAL32.dll` and `EaxMan.dll` of `code/`, `codemp/` and `codeJK2/`, the x86 binaries of `lib/SDL2`; the video capture no longer tests `s_UseOpenAL` (`cl_avi.cpp`). The setting `s_UseOpenAL` and the menus that name it are left to plan step 15.
- The `#if 0 //_M_IX86` blocks of `tr_ghoul2.cpp` (rd-vanilla, rd-dedicated, rend2) and `rd-dedicated/tr_model.cpp`.
- netcodec: the 32-bit branch of `FloorI` (`src/numeric.h`), the x86 flags, the 32-bit names (`i386` of the AddressSanitizer DLL, the fuzzer runtime, `ARCH_STRING`), the target `netcodec_engine_cxx11` (`engine.h` is no longer held to C++11: nested namespace, `[[nodiscard]]`), `netcodec_legacy` in C++20; the configuration stops on a 32-bit target; D1: `netcodec_pmove_101`, `stubs101.c`, `prelude101.h` and the `JKA101` code of `pmove_det.c`.

**Presets and scripts.** The presets `msvc-x86`, `mingw-clang-x86` and `gcc-x86`; the x86 runs of `validate.bat` and `validate.sh`, whose trainers now run in x64 (`msvc-x64`, `gcc-release`): the x64 trainers write the committed tables unchanged (checked here with clang). `M32=1` of `ab_gcc_multi.sh`, `ABM_ARCH` of `ab_msvc.bat`, the x86 preset named by `ab_clang.sh`; the x86 builds of `tools/mathlib` (C++20 there too); `tools/cpubench` without `-msse2`, `tools/cpubench` and `tools/fieldinfo` in C++20. The GitHub workflows and the Dockerfile: their x86 and i386 parts.

**Comments.** The 13 lines that named a person as the author of a decision (the A/B scripts, `pmove_det.c`, `bg_pmove.c`, `cg_predict.c`, the gamestats scripts) state the decision with its date, or the role.

**String literals (16 November 2026).** The first Windows validation stopped on 295 MSVC errors, all of one kind: `/permissive-` implies `/Zc:strictStrings`, under which a string literal (a `const char` array) no longer converts to `char *`. GCC and clang accepted the conversion only because the build gave them `-Wno-write-strings`; without it clang listed 2,511 places (multiplayer and shared 1,016, single player 505, Jedi Outcast 990). The fix is const-correctness, the compiler checking each step: `const char *` wherever a string is only read, and nothing else.
- Parameters that only read their string: the botlib's (`botimport.Print`, `SourceError`, `ScriptError`, `LibVar*`, `PC_*TokenString`, the `AAS_*ForBSPEpairKey`, ...), the engine's (`GLimp_LogComment`, `SV_Shutdown`, `SV_GetStringEdString`, `Com_Filter`, `Com_SkipTokens`, `FS_idPak`, `Sys_ListFiles`, ...), the cgame's (`CG_PositionEntityOnTag`, `cgi_UI_*`, ...), the game's (`Debug_Printf`, `G_SetSaber`, `G_FilterPacket`, ...).
- Return types where a function returns a literal or text its callers only read: `Cmd_Argv`, `Cvar_VariableString`, `Info_ValueForKey`, `Key_GetBinding`, `NET_ErrorString`, the descriptions of commands and settings, the skin parser's token, a bone's name, the animation file names; the interfaces follow (the renderer's `Cmd_Argv` and `Cvar_VariableString`, the single-player game's `argv`, the botlib's and the game's `BotLibVar*` and `AAS_*` pointers), and about 120 callers keep the result in a `const char *`.
- Fields and tables that hold literals: the botlib's field definitions, built-ins and directives, `netsrcString`; in single player and Jedi Outcast the entity's `classname`, `NPC_type`, `targetname`, `script_targetname`, `message`, `fxFile`, the saber's `model` and `saberModel`, the spawn and saber keyword tables, the cgame's name tables. Those entity fields point at a literal or at zone memory that the game frees when `gi.bIsFromZone` says so: the free takes the pointer through `(void *)`.
- ICARUS reads the strings the game gives it: `GetString` takes a `const char **` (single player, Jedi Outcast).
- Two bugs found on the way: `SV_ParseCIDRNotation` (the bans' address parser) wrote a NUL into its caller's string, the command's argument, and now works on its own copy; the single-player `CBlockStream` wrote its file header with `sizeof` of a pointer (8 bytes on a 64-bit target, where the header is "IBI" and its NUL): the header is now an array, so `sizeof` is its 4 bytes.
- `-Wno-write-strings` is removed from the build: GCC and clang report what MSVC refuses.

**GCC 15, Clang 23 on Linux, and MSVC on every target (16 November 2026).** The Linux VM moved to Ubuntu 22.04 with GCC 15 and Clang 23 (section 5), and the validations built every target there and with MSVC, rend2 and Jedi Outcast included, which neither GCC nor MSVC had built in this step. `validate.sh`: `ALL OK`. GCC 15 no longer reports the two false warnings of GCC 12.2 (`stringed_ingame.cpp`, `cg_effects.c`), and none of the fixes above comes back. What was left, fixed the same way:
- MSVC refused to link Jedi Outcast's game module: `NPC_spawn.cpp` declared `extern char *TeamNames[]` while the definition is `const char *` since the string literals were made const. MSVC puts a variable's type in its symbol, GCC and clang do not, so only MSVC saw the two disagree; the declaration is const now.
- MSVC 18 `C4875`, 623 times: gsl-lite 0.41 writes `[[gsl::suppress(f.6)]]` without a string, which MSVC now deprecates (gsl-lite 1.1 writes a string). gsl-lite stays as it is: a pragma around its only include (`shared/qcommon/safe/gsl.h`); moving to gsl-lite 1.x changes its API (`string_span` removed in 1.0) and is left for later.
- GCC 15 `-Wdangling-pointer` in `md4.cpp` (both engines; the checksums of the maps, the pk3s and the single-player saves): a file-scope pointer kept the address of `mdfour()`'s local context after it returned; the context is now passed to each function, the same computation.
- Jedi Outcast: the same 25 address tests and 11 `memset` as the single-player tree, fixed alike (`navInfo_t` holds a trace); `SetMiscModelModels` and `SP_misc_model_breakable` with a long model name. The latter's single-player copy bounded its first copy but not the NUL at `len` nor the `strcat`s: both trees build the names with `Com_sprintf` now.
- Clang 23 on Linux: `fs_copyfiles` (set, read only by Windows code: now Windows only) and `TTY_eof` (set, never read: removed).
- rend2 (`codemp/rd-rend2`), built by GCC for the first time, gave 48 `-Wsign-compare` (GCC's `-Wall` reports them in C++, clang's does not), among them in its loader of IQM models (`tr_model_iqm.cpp`), which reads the pk3s' data and whose range check can overflow an `int`, and a few unset reads (`G2_Pause_Bone_Anim`, `parentFlags`, an HDR lightmap's `buf_p`). rend2 was removed instead (section 1): ModernJK uses rd-vanilla only.
